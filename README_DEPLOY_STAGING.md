# Langkah deployment V2 — HARUS staging terlebih dahulu

1. Simpan backup ZIP master `main` original dan backup SQL lengkap (termasuk auth.users + kebijakan/trigger) di tempat privat. Jangan unggah credential atau dump personal ke repo.
2. Checkout branch `v2-id-login-staging` di repo lokal GitHub. Pastikan `git branch --show-current` bernilai `v2-id-login-staging`. Salin isi source paket ini ke root repo branch itu; jangan menimpa Git metadata `.git`. Periksa `git status` dan `git diff` sebelum commit.
3. Siapkan **Supabase staging TERPISAH**, dengan tabel `users`, `cases`, `evidence_files`, `case_logs`, migrasi PIC dan policy existing. Buat 5 akun UJI, jangan gunakan user/password perusahaan nyata. Sesuaikan profil `id_user` dengan UUID Auth staging. Dapatkan bukti query sebelum migrasi.
4. Di SQL Editor Supabase **STAGING**, jalankan `sql/05_LOGIN_ID_DAN_RATE_LIMIT_MIGRASI.sql` dan periksa ID dengan nama dan role. Lalu jalankan `sql/08_ACCOUNT_SECURITY_V2_STAGING.sql` dan `sql/09_RPC_GUARD_FORCED_PASSWORD.sql`. **Jangan jalankan ulang SQL 01–03 jika sudah diterapkan**. Untuk produksi, tinjau dan uji RLS terhadap skema aktual dulu.
5. Hubungkan Vercel **Preview environment** ke Supabase staging: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (server-only), dan setting Google Drive/Sheets khusus uji. Jangan gunakan database, folder Drive atau Spreadsheet yang aktif. URL Supabase produksi lama diblokir oleh `/api/public-config` saat `VERCEL_ENV=preview`.
6. Push ke branch staging → dapatkan URL Preview Vercel. Uji GET `/api/public-config` hanya mengembalikan URL + publishable key publik, **tidak ada secret**. Uji 5 akun dengan ID dan password, dan coba akses laporan tanpa login.
7. Uji ganti password mandiri. Untuk uji lupa password, di **terminal privat** dengan `SUPABASE_URL` dan `SUPABASE_SERVICE_ROLE_KEY` staging pada environment lokal:
   `python scripts/admin_reset_password.py --id NP-STF-001` (dry run), lalu `python scripts/admin_reset_password.py --id NP-STF-001 --execute --confirm RESET_AKUN_STOCKTRACE_TEROTORISASI`. Berikan password sementara secara privat, uji bahwa akses laporan ditahan sampai password diganti.
8. **Penggantian email Auth lama**: jika benar-benar akan mengganti email lama, gunakan `scripts/migrate_auth_email.py` dengan domain alias yang benar-benar kamu kelola. Mulai dari dry-run: `python scripts/migrate_auth_email.py --domain auth.DOMAIN-PRIVAT-MILIKMU.id`; jangan jalankan `--execute` sebelum backup dan lima akun diuji. Supabase password provider tetap memerlukan email internal; ini **tidak menghapus kolom email**.
9. Coba upload video ke **folder Drive staging**: 5 MiB, 25 MiB dan 100 MiB dari laptop, Chrome Android dan Safari iPhone. CORS Google Drive, upload ulang/interupsi, file id, metadata, dan download besar harus lolos. Kalau CORS menolak, jangan aktifkan fitur untuk Staff; gunakan rute penyimpanan lain sebelum produksi.
10. Uji status PIC hanya Leader, membaca kasus sesuai RLS, pembatas login/password, Sheets, serta responsif berbagai layar. Baru setelah uji penerimaan, buat PR dari branch staging ke main dan deploy.

**Penting**: Mengubah branch GitHub **tidak** otomatis mengisolasi database dan Drive. Lima ID pada SQL 05 dapat terbentuk menurut urutan alfabet nama. Verifikasi secara manual sebelum membagikan ID ke Staff.
