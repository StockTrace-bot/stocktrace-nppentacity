StockTrace V2.3 Performance Optimization — source audit

Basis: complete StockTrace source ZIP uploaded from the GitHub main branch, identified as V2.2.3.

Performance findings addressed:
- Blocking third-party scripts on login and dashboard pages.
- Sequential profile/security and initial dashboard requests.
- Oversized dashboard and V2.1 list queries.
- Sequential multi-file evidence uploads and per-file metadata writes.
- Repeated Google OAuth refresh and Drive folder checks.
- Repeated ID-login backend lookups.

Implemented changes:
- Deferred external UI scripts and added CDN preconnect hints.
- Added short cache headers to the public-only Supabase config endpoint.
- Parallelized independent login/dashboard and upload authorization checks.
- Reduced selected fields and added short-lived view data caches.
- Increased V2.1 pagination to 1,000 rows while filtering archived rows at query time.
- Added two-file upload concurrency and batch metadata inserts with individual fallback.
- Added warm-instance Google OAuth token caching and short Drive folder permission caching.
- Preserved original evidence files; no resizing or recompression is applied.

Automated checks:
- JavaScript/MJS syntax checks: passed.
- Automated test suite: 84 passed, 0 failed.

Database and deployment:
- No SQL migration, table change, RLS change, role change, OAuth credential change, or Vercel environment variable change is required.
- This ZIP is source code only. It has not been deployed to Vercel and no live latency measurement has been performed.
- After deployment, test login, dashboard, one small photo, multiple photos, one PDF/video, and the existing Drive/Sheets integrations on the actual operating devices and network.

No service-role key, OAuth secret, refresh token, or service-account JSON was added to the package.
