Kebijakan Privasi StockTrace

Pembaruan: 28 Oktober 2026 • Berlaku untuk prototipe StockTrace yang dikelola tim proyek

StockTrace adalah prototipe dokumentasi dan penelusuran kasus selisih stok pada studi kasus ritel. Halaman ini menjelaskan praktik pengelolaan data yang dirancang dan diimplementasikan pada aplikasi yang menggunakan autentikasi Supabase, backend Vercel, dan penyimpanan bukti Google Drive. Sebelum digunakan untuk data nyata perusahaan, konfigurasi teknis, izin penggunaan, dan kebijakan internal harus ditinjau bersama pihak yang berwenang.

1. Jenis informasi yang diproses

  • Akun: email, identitas profil pengguna yang didaftarkan, peran Staff/Leader, dan informasi sesi autentikasi yang dikelola Supabase.
  • Laporan kasus: ID kasus, tanggal dan waktu, SKU, nama produk, stok sistem, stok fisik, selisih, dugaan penyebab, kronologi, dan status.
  • Bukti: file yang dipilih pengguna (misalnya foto, PDF, video singkat, dokumen penjualan atau penerimaan), nama file, ID file Google Drive, dan metadata terkait kasus.
  • Riwayat: pengguna yang melakukan tindakan, waktu, perubahan status, dan catatan tindak lanjut.
  • Data teknis: catatan operasional minimum yang dihasilkan oleh penyedia hosting, autentikasi, dan layanan penyimpanan untuk keamanan atau penanganan error.

2. Tujuan penggunaan

Informasi digunakan untuk autentikasi pengguna, pencatatan dan pelacakan kasus, pengelolaan dokumen pendukung, pemeriksaan oleh pengguna yang berwenang, pembuatan rekap, dan penanganan kendala teknis. Informasi Google Drive yang diakses melalui API hanya digunakan untuk fungsi penyimpanan dan pengambilan berkas yang relevan dengan aplikasi, bukan untuk iklan, penjualan data, atau profil pemasaran.

3. Google Drive API dan ruang akses

StockTrace menggunakan izin OAuth Google Drive terbatas https://www.googleapis.com/auth/drive.file. Dalam konfigurasi prototipe, backend menggunakan akun penyimpanan yang telah memberikan izin untuk membuat berkas bukti di folder tujuan yang dikonfigurasi. Aplikasi mengakses berkas yang dibuat atau diberikan akses kepada aplikasi dalam cakupan tersebut; tidak meminta izin untuk melihat seluruh dokumen pribadi lain di Drive pengguna.

Token Google OAuth disimpan di pengaturan rahasia backend pada platform hosting dan tidak seharusnya dikirim sebagai bagian dari HTML publik. Pengguna dapat meninjau dan mencabut akses aplikasi pada pengaturan keamanan Akun Google; pencabutan akses dapat menghentikan kemampuan upload atau unduh aplikasi.

4. Penyimpanan dan penyedia layanan

Data akun dan metadata kasus disimpan menggunakan Supabase; file bukti disimpan pada Google Drive yang dikonfigurasi; fungsi web dan penghubung layanan berjalan melalui Vercel. Data yang diperlukan diproses oleh penyedia tersebut untuk menjalankan layanan. File Drive tidak perlu dibagikan secara publik untuk ditampilkan lewat mekanisme akses aplikasi yang berwenang.

5. Akses dan perlindungan

Akses diarahkan melalui autentikasi Supabase dan kontrol berbasis peran; rincian pembatasan akses mengikuti kebijakan Row Level Security (RLS) dan konfigurasi backend yang aktif. Akun Staff dan Leader dapat mempunyai cakupan akses berbeda. Tidak ada layanan internet yang sepenuhnya bebas risiko; keamanan harus dievaluasi secara berkala sebelum menyimpan dokumen sensitif.

6. Penyimpanan, koreksi, dan penghapusan

Untuk tahap prototipe, jadwal retensi dan prosedur penghapusan data secara menyeluruh belum ditetapkan sebagai kebijakan resmi perusahaan. Permintaan koreksi atau penghapusan data uji dapat disampaikan kepada kontak di bawah untuk dievaluasi berdasarkan kewenangan pengelola. Penghapusan metadata di Supabase dan file asli di Google Drive dapat memerlukan tindakan terpisah.

7. Data sensitif dan penggunaan terbatas

Pengguna tidak boleh mengunggah informasi pribadi pelanggan, dokumen finansial rahasia, atau rekaman tanpa persetujuan yang sesuai. Dalam fase pengujian, gunakan file simulasi yang tidak mengandung data personal. Data dari Google API tidak digunakan untuk tujuan periklanan atau dibagikan untuk penggunaan pemasaran.

8. Hak pengguna dan kontak

Untuk menanyakan pemrosesan data atau meminta peninjauan akses, koreksi, dan penghapusan data uji, hubungi tim pengelola proyek di stocktrace.nppentacity@gmail.com. Pastikan alamat kontak ini tetap aktif sebelum memublikasikan halaman.

9. Perubahan kebijakan

Dokumen ini dapat diperbarui mengikuti pengembangan aplikasi, perubahan integrasi, dan kesepakatan pihak terkait. Tanggal pembaruan terbaru dicantumkan di bagian atas halaman.
